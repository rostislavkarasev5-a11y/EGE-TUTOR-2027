# ADR-0014: Python Sandbox на сервере — отдельный контейнер без сети

- Статус: Proposed
- Дата: 2026-10-07
- Дополняет: ADR-0008 (Sandbox на Windows), ADR-0013 (сайт на своём сервере)

## Контекст

Phase 3 добавляет запуск программ на Python для заданий по информатике. ADR-0008 описывает
Windows: Docker Desktop, запасной WSL2. Но основным местом работы стал сервер (ADR-0013),
где сайт сам работает внутри Docker-контейнера.

На сервере есть два очевидных способа, и оба плохие:
- дать контейнеру сайта доступ к Docker (`/var/run/docker.sock`) — это всё равно что дать
  ему права root на сервере;
- запускать программы прямо в контейнере сайта — они смогут прочитать базу и пароль
  и обратиться к сайту по сети, а `unshare --net` в обычном контейнере запрещён.

## Решение

1. **Отдельный контейнер `runner`** в том же `docker-compose`, только для запуска программ:
   - `network_mode: none`: у программ нет сети совсем, ни в интернет, ни к сайту;
   - корневая файловая система только на чтение, рабочая папка во временной памяти (tmpfs);
   - `cap_drop: ALL`, `no-new-privileges`, лимиты контейнера: 1 CPU, 512 МБ, 128 процессов;
   - базы, пароля и личных файлов внутри нет.
2. **Сайт передаёт программу через Unix-сокет** в общем томе (`/run/ege-runner/runner.sock`).
   Сети между контейнерами для этого не нужно.
3. **Каждый запуск внутри `runner`** — движок Linux-native из архитектуры (раздел 9):
   отдельная временная папка, пользователь без прав, `python -I`, чистое окружение,
   `RLIMIT_CPU`, `RLIMIT_AS`, `RLIMIT_NPROC`, `RLIMIT_FSIZE`, таймер с убийством всей
   группы процессов. Лимиты по умолчанию из `config/app.toml` (10 с, 256 МБ).
4. **На Windows (CLI) — как в ADR-0008:** тот же образ `runner` запускается через
   Docker Desktop на каждый запуск (`docker run --rm --network none ...`). WSL2 —
   запасной вариант на будущее; до реализации он честно сообщает, что недоступен.
5. Если `runner` не запущен или Docker не установлен, Sandbox честно сообщает «недоступен»,
   остальные функции работают как раньше.

## Последствия

- Один и тот же движок запуска на сервере и на Windows, один набор тестов на «злые» программы.
- На сервере добавляется ещё один небольшой контейнер; установка и обновление делают это сами.
- Для CLI на Windows понадобится Docker Desktop (как и было в ADR-0008).

## Рассмотренные альтернативы

- **Docker-сокет в контейнере сайта** — опасно: права root на сервере.
- **Запуск в контейнере сайта** — программа видит базу, пароль и сеть.
- **gVisor / Firecracker** — сильнее изоляция, но сложнее установка; для своего кода
  одного пользователя избыточно (модель угроз — раздел 9 архитектуры).
