# ADR-0015: Mastery v0, ошибки и повторения — недостающие детали формул

- Статус: Accepted
- Дата: 2026-10-07
- Дополняет: ADR-0006 (Mastery v0), архитектура, разделы 5.4–5.5

## Контекст

Архитектура и ADR-0006 задают формулу свидетельства `e` и вес `w`, но оставляют открытыми
детали, без которых Phase 4 не написать: как именно «новые свидетельства важнее старых», как
растёт стабильность, как считать уверенность, что попадает в `prediction_log`, по каким правилам
классифицируются ошибки и как считается приоритет паттерна. Это правила обучения, поэтому их
нельзя придумать молча — фиксируем здесь. Все числа — значения по умолчанию в
`config/mastery.toml`, их можно менять без изменения кода.

## Решение

### Навык: M_raw и уверенность

Учитываются завершённые попытки на задачи с этим навыком (ответ дан или сдался; брошенные —
нет). Для каждой попытки `e` и `w` — по ADR-0006 (сдался → правильность 0).

```
M_raw = Σ wᵢ·dᵢ·eᵢ / Σ wᵢ·dᵢ,     dᵢ = recency_decay ^ (сколько попыток по навыку было после i-й)
уверенность = 1 − exp(−Σ wᵢ·dᵢ / confidence_scale)
```

`recency_decay = 0.8`, `confidence_scale = 3.0`. Без попыток навык «не изучен» (M нет).

### Забывание и стабильность

```
M(сегодня) = M_raw × exp(−дни_с_последней_практики / стабильность)
```

Стабильность начинается с `initial_stability_days = 3`. После каждой попытки:
- успех (`e ≥ success_threshold = 0.6`) не раньше чем через `min_review_gap_days = 1` день после
  прошлой практики → стабильность × `stability_growth = 2.0` (не больше `max_stability_days = 180`);
- провал (`e < failure_threshold = 0.3`) → стабильность × `stability_after_failure = 0.5`
  (не меньше начальной);
- иначе (или успех в тот же день) — без изменений.

Срок повторения — день, когда прогноз M опустится ниже `review_threshold = 0.7`;
если M_raw уже ниже порога — повторять сразу.

### Темы и номера заданий

Mastery темы и номера задания ЕГЭ — среднее M изученных навыков, взвешенное их уверенностью,
плюс доля изученных навыков (чтобы «один навык из пяти» не выглядел как освоенная тема).

### prediction_log

При начале каждой попытки записывается предсказание `P = среднее M навыков задачи` (неизученный
навык считается 0) и `model_version`. После завершения — факт: 1, если решено самостоятельно
(верно и без подсказок), иначе 0. Задачи без навыков не логируются. Это данные для калибровки
(Brier score, log-loss) — сама калибровка позже.

### Снимки истории

После каждой попытки пересчитываются только навыки этой задачи; снимок `mastery_snapshot`
за **сегодняшний** день перезаписывается, прошлые дни не трогаются никогда. Команда пересчёта
по всей истории пересчитывает текущие значения, но не прошлые снимки.

### Ошибки: правила классификации

Ошибкой считается попытка с итогом «неверно», «неверный формат» или «сдался». Для каждого навыка
задачи записывается одна ошибка (без навыков — одна без навыка). Правила по порядку:

| Условие | Категория | Уверенность |
|---|---|---|
| неверный формат | `FORMATTING` | 0.9 |
| последний запуск программы в попытке: синтаксическая ошибка | `SYNTAX` | 0.9 |
| … превышено время | `ALGORITHM` | 0.6 |
| … ошибка во время работы или неверный вывод на тестах | `PROGRAMMING` | 0.6 |
| ответ отличается только знаком | `CARELESS` | 0.6 |
| числа отличаются в 10ⁿ раз или теми же цифрами в другом порядке | `ARITHMETIC` | 0.4 |
| время больше 2× норматива | `TIME` | 0.4 |
| сдался | `TOPIC_GAP` | 0.5 |
| иначе | `TOPIC_GAP` | 0.3 |

Пользователь может поменять категорию (кто классифицировал — `USER`, уверенность 1.0).
Исходная запись правила сохраняется в истории.

### Паттерны ошибок

Паттерн = (навык, категория), как в архитектуре:

```
приоритет = база_категории × (1 + 0.5 × (повторов − 1)) × exp(−дни_с_последней / freshness_days)
```

`freshness_days = 14`, базы категорий — в `config/mastery.toml` (`TOPIC_GAP` и `ALGORITHM` выше
всего, `FORMATTING` и `CARELESS` ниже). Паттерн закрывается после 3 подряд самостоятельных верных
решений на этот навык в разные дни; новая ошибка открывает его снова.

### Очередь повторений

Сначала навыки, у которых подошёл срок повторения (по возрастанию M), потом открытые паттерны
ошибок (по убыванию приоритета). Кнопка «Повторить» выдаёт проверенную задачу на первый навык
из очереди в режиме `REVIEW`.

## Последствия

- Все коэффициенты в `config/mastery.toml`; тесты проверяют свойства (e и M в [0, 1], подсказка
  не выгоднее самостоятельного решения, забывание не увеличивает M), а не конкретные числа.
- Классификация правилами грубая; ИИ-классификация — Phase 6, вопрос «что пошло не так» уже есть.
- План занятий (Phase 7) будет брать задачи из очереди повторений.

## Рассмотренные альтернативы

- **FSRS целиком** — точнее, но требует данных для настройки; v0 должна работать с первого дня.
- **Экспоненциальное сглаживание по времени, а не по номеру попытки** — хуже работает, когда
  много попыток в один день.
- **Пересчёт прошлых снимков** — нарушил бы правило «история не переписывается задним числом».
