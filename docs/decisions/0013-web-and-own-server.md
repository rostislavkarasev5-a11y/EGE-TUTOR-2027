# ADR-0013: Сайт на собственном сервере (VPS)

- Статус: Accepted
- Дата: 2026-10-07
- Меняет: ADR-0003 (FastAPI раньше Phase 12), ADR-0004 (где хранятся личные данные),
  ADR-0008 (где работает Sandbox), порядок фаз в Roadmap

## Контекст

Владелец попросил «перенести всё на VPS-сервер и сделать сайт для удобства» и выбрал делать
это сразу после Phase 2. По утверждённому плану Web — последняя Phase 12 («FastAPI поверх того
же `TutorApp`»), а личные данные хранятся только на компьютере пользователя (ADR-0004).

Сайт в интернете добавляет то, чего раньше не было: вход по паролю, защищённое соединение,
резервные копии на сервере и обновление сервера без участия владельца.

## Решение

### 1. Сайт — ещё один интерфейс над тем же `TutorApp`

- **FastAPI + Jinja2-шаблоны + uvicorn.** Страницы собираются на сервере, без отдельного
  фронтенда и сборки JavaScript. Страницы работают и на телефоне.
- Сайт, как и CLI, только вызывает `TutorApp` и показывает результат. CORE, порты и правила
  обучения не меняются. CLI продолжает работать на Windows как раньше.
- Первая версия сайта повторяет то, что уже есть: главная (состояние, даты экзаменов TBD),
  решение задач (ответ, подсказки, «сдаюсь», похожая), проверка эталонных ответов,
  история попыток, список задач, профиль, импорт файла с задачами (предпросмотр → запись),
  скачать резервную копию. Новые функции следующих фаз сразу получают и команду, и страницу.

### 2. Вход

- Один пользователь — владелец. Регистрации нет.
- Пароль задаётся на сервере командой `ege-web set-password`; хранится только хеш
  (Argon2, библиотека `argon2-cffi`). Пароль не попадает ни в Git, ни в логи.
- Сессия — подписанная cookie (`HttpOnly`, `Secure`, `SameSite=Lax`), 30 дней. Секрет подписи
  генерируется на сервере при установке и хранится в `/etc/ege-tutor/web.env` (не в Git).
- Защита от подбора: после 5 неверных паролей подряд вход блокируется на 15 минут.
- Все формы, меняющие данные, защищены CSRF-токеном.

### 3. HTTPS

- Перед приложением стоит **Caddy**: сам получает и продлевает сертификат Let's Encrypt.
- Адрес по умолчанию — бесплатный `<IP-сервера>.sslip.io` (регистрация не нужна).
  Свой домен можно подключить позже одной строкой в настройках.
- Приложение слушает только внутренний адрес; снаружи открыты лишь порты 80/443 и SSH.

### 4. Сервер и обновления

- VPS с **Ubuntu 24.04**, минимум 1 vCPU, 2 ГБ RAM, 20 ГБ диска. Арендует и оплачивает владелец.
- Всё запускается в **Docker Compose** (контейнеры `app` и `caddy`). Docker понадобится и для
  Sandbox в Phase 3, поэтому на сервере Sandbox работает в обычном Linux-Docker
  (ADR-0008 остаётся в силе для Windows).
- Установка — один скрипт `deploy/install-server.sh`, который владелец один раз вставляет
  в консоль сервера по инструкции.
- **Обновление без участия владельца:** таймер на сервере раз в 10 минут проверяет ветку `main`
  публичного репозитория; если есть новый коммит, пересобирает и перезапускает приложение
  (перед этим делает резервную копию базы, миграции Alembic применяются при старте).
  Ключи от сервера не хранятся ни в GitHub, ни у Claude.

### 5. Данные и резервные копии

- Личная база SQLite лежит на сервере в `/var/lib/ege-tutor/` (вне Git, вне контейнера).
  Данные по-прежнему принадлежат приложению, а не ИИ (принцип 1); меняется только место:
  компьютер владельца **или** его собственный сервер.
- Резервная копия каждую ночь (`sqlite3 .backup`, проверка целостности), хранятся 14 дней,
  плюс копия перед каждым обновлением.
- На сайте кнопка «Скачать копию базы» — владелец может держать копию у себя.
- Задачи из сборников и ФИПИ, загруженные через сайт, хранятся только на сервере, в Git
  не попадают (ADR-0004 в остальном без изменений).

### 6. Место в Roadmap

- Новая фаза **«Web и сервер»** выполняется сразу после Phase 2. Номера остальных фаз
  не меняются, чтобы не ломать ссылки в документах; Phase 12 становится этой фазой.
- Новые зависимости этой фазы: `fastapi`, `uvicorn`, `jinja2`, `python-multipart`,
  `argon2-cffi`, `itsdangerous`. Тесты сайта — через `httpx`/`TestClient` (dev-зависимость).

## Последствия

- Решать задачи можно с телефона и любого компьютера; дома CLI тоже работает.
- Сервер — новая точка отказа и ответственность: бэкапы, обновления, безопасность входа
  становятся частью проекта уже сейчас, а не в Phase 11.
- Две базы (на компьютере и на сервере) не синхронизируются. По умолчанию основная — на
  сервере; перенос локальной базы на сервер — загрузка копии через сайт.
- Exam Mode и правило «без ИИ» не меняются: сайт не добавляет никаких вызовов ИИ.

## Рассмотренные альтернативы

- **Оставить сайт на Phase 12** — владелец выбрал делать сейчас.
- **Отдельный фронтенд (React/Vue)** — сложнее сборка и поддержка, для одного пользователя
  не нужен.
- **Деплой из GitHub Actions по SSH** — пришлось бы хранить SSH-ключ сервера в GitHub;
  схема «сервер сам забирает обновления» проще и безопаснее для публичного репозитория.
- **Nginx + certbot** вместо Caddy — больше ручной настройки сертификатов.
- **Хостинг без своего сервера (PaaS)** — у SQLite нет постоянного диска на многих PaaS,
  а Sandbox в Phase 3 требует Docker.

Владелец подтвердил решение («Утвердить») 2026-10-07.
