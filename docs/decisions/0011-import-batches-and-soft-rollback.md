# ADR-0011: Импорт пачками, предпросмотр и мягкая отмена

- Статус: Accepted
- Дата: 2026-10-07

## Контекст

ADR-0007 требует единый конвейер импорта с проверкой, поиском дублей, отчётом и откатом пачки
(`import_batch`). Нужно уточнить, как именно работает откат: если удалять задачи физически,
в будущем пропадут попытки и ошибки, которые на них ссылаются, а это нарушает принцип
«сырые попытки пользователя никогда не удаляются из истории».

## Решение

1. `ege import ФАЙЛ` по умолчанию только проверяет файл и показывает отчёт. Запись — только
   с флагом `--apply`.
2. Записываются только задачи без ошибок, одной транзакцией. Предупреждения запись не блокируют.
   Ошибочные задачи перечислены в отчёте с номером и понятной причиной; отчёт сохраняется
   вместе с пачкой.
3. Отмена (`ege undo-import N`) — мягкая: задачи пачки получают `is_active = false` и больше не
   выдаются, пачка получает статус `ROLLED_BACK`. Записи не удаляются.
4. Дубли ищутся по хэшу (предмет + номер задания + условие без учёта регистра и лишних
   пробелов) среди действующих задач и внутри файла. Уникальность в БД — частичный индекс
   «только среди действующих», поэтому после отмены тот же файл можно загрузить заново.
5. Файлы к задачам копируются в `data/private_content/assets/` под именем по SHA-256
   (одинаковые файлы хранятся один раз).
6. При импорте можно указать только статусы `UNVERIFIED` и `REVIEWED`. `AI_GENERATED` задачи
   всегда импортируются как `UNVERIFIED`.

Владелец подтвердил решение («Скрывать задачи») 2026-10-07.

## Последствия

История никогда не теряется, отмену можно объяснить и проверить. База немного растёт за счёт
отменённых задач — для личного использования это несущественно.

## Рассмотренные альтернативы

- Физическое удаление при откате — проще, но ломает принцип сохранения истории начиная с Phase 2.
- Импорт сразу без предпросмотра — легко случайно загрузить файл с ошибками.
