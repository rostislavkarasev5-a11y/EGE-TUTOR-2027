# ADR-0004: Публичный репозиторий, личные данные только локально

- Статус: Accepted
- Дата: 2026-10-07

## Контекст

Владелец проекта решил сделать репозиторий публичным. В проекте будут личные данные (попытки, ошибки, расписание), ключ Claude API и задачи из сборников и ФИПИ, защищённые авторским правом.

## Решение

В Git попадают только код, тесты, документация, конфигурация по умолчанию и контент, который можно публиковать. Только на компьютере пользователя:

| Что | Где |
|---|---|
| База данных и бэкапы | `data/` |
| Задачи из сборников, ФИПИ, личные материалы | `data/private_content/`, `private_assets/` |
| Ключи API и секреты | `.env` (пример без значений — `.env.example`) |
| Локальные настройки | `config/local.toml` |

Защита в два слоя:
1. `.gitignore` закрывает эти пути (проверяется тестом `tests/unit/test_repo_safety.py`).
2. `scripts/check_secrets.py` в CI падает, если в отслеживаемых файлах есть запрещённые пути или строки, похожие на ключи (Anthropic, GitHub, AWS, приватные ключи, заполненные `*_API_KEY=` / `*_TOKEN=` и т. п.).

В репозиторий не добавляются реальные персональные данные пользователя (включая личное расписание) — только обезличенные примеры.

## Последствия

Код и архитектура открыты. Бэкап личной базы — ответственность приложения (`ege backup`, Phase 11), а не Git. Тестовые «секреты» в тестах собираются во время выполнения, чтобы не срабатывала проверка.
